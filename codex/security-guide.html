CHATGPT LEARN · SECURITY

安全不是一个开关，而是一组边界

Security（安全）栏目说明 ChatGPT 与 Codex 开发工具可访问什么、敏感操作如何审查、代码漏洞如何调查，以及网络安全工作如何受控。

重要区分：本页概览个人开发时的权限和安全操作，并介绍 Codex Security 与 Cyber safety。组织管理员如何部署策略属于相关但更专门的管理工作，应另看 Administration 文档。
01

先看安全控制的四层

Security map

限制能力边界

  • Permission profile / sandbox：限制文件系统、命令或网络访问范围。
  • Approval policy：规定哪些操作要暂停并请求审批。
  • Managed requirements：组织层约束用户可以采用的设置。

发现和处理风险

  • Auto-review：审查特定敏感操作或审批请求。
  • Codex Security：对代码库进行漏洞分析、报告和修复协作。
  • Cyber safety：规定获准的网络安全模型、访问和参与边界。

这些层处理不同问题，安全设计要结合使用：权限设置限制“能做什么”，审批决定“何时要停下来”，审查帮助判断“操作是否符合策略”。

02

Permission 与 Sandbox：能访问什么

Access boundary

Permission profile（权限配置档案）定义允许访问的资源和操作；Sandbox（沙箱）是隔离执行环境并约束本地文件与网络访问的一种机制。官方建议选择足以完成任务的最窄权限配置，尤其是在授予写入或外网访问时。

控制回答的问题常见理解错误
权限档案文件、命令和网络资源分别允许哪些访问？把权限扩大当作解决所有执行失败的通用办法。
沙箱命令实际能触及哪些文件与网络？以为沙箱等于审批，或审批等于沙箱。
项目 / 工作树边界当前任务围绕哪些项目文件进行？为方便而让一个任务访问无关仓库或整个文件系统。
外部工具权限插件、MCP、浏览器、应用连接可以访问什么？以为本地沙箱自动管控所有云端连接与外部应用。

当任务仅需阅读时，使用只读边界；需要编辑时，尽量限制在当前工作区。网络访问、应用连接及云端环境可能采用独立控制，须按各自环境分别确认。

03

Approval 与 Auto-review：操作如何被审查

Human approval · Automatic review

Approval（审批）策略决定 Codex 何时暂停并要求批准；Auto-review（自动审查）可以在支持的模式下把符合条件的审批请求交给自动安全审查。自动审查改变了审核方式，不会自动拓宽沙箱或权限范围。

Ask for approval

需要批准时让用户决定是否继续。适合希望直接了解并审阅越界操作的情形。

Approve for me / Auto-review

在可用环境中让自动审查处理符合条件的请求；判断到可能不安全的操作时仍可能要求用户决定。

牢记：approval 管“是否暂停等待审查”；sandbox / permissions 管“访问边界在哪里”。自动审批不能视为更宽访问授权。

04

Codex Security：发现并处理代码漏洞

Code security review

Codex Security 面向代码安全工作：扫描代码、调查发现项、审阅修复，并协助跟踪漏洞。它关注“代码是否存在漏洞和风险”，与沙箱权限（代理能访问什么）属于不同层面。

Security Review

分析代码并给出有证据支撑的发现，帮助工程师定位和理解潜在漏洞。

扫描、分诊、修复

可从安全扫描开始，逐项评估发现，改进威胁模型，并审阅拟议修复。仍需维护者验证与决定。

是否使用 Cloud、Plugin、CLI 或 SDK，取决于代码位置与工作方式；产品入口与套餐可用性以当前官方页面为准。

05

Cyber safety：授权范围必须清楚且可执行

Authorized cybersecurity

网络安全专用工作需要明确授权目标、允许动作、工具、时间窗口、排除对象、数据处理方式和停止条件。任务描述本身不能强制执行这些边界；应通过独立的文件、网络、身份和工具控制尽可能落实。

Models & Trusted Access

针对获准的防御性网络安全任务，专门说明相关模型与访问要求。敏感能力需要相应批准与受控使用。

Recommended configuration

使用最小权限和明确范围配置，只允许已批准的实验目标；排除生产系统、无关主机、凭据窃取、持久化或数据外传等越界行为。

适用边界：此内容针对获授权的防御性安全工作。执行前须确认授权范围与停止条件；通用编码安全审查不等于渗透测试授权。

06

每次开始任务前的安全检查顺序

A practical checklist
步骤检查问题
1 · 识别环境任务在本机、工作树还是 Cloud 执行？当前实际连接了哪些文件、服务和工具？
2 · 收窄权限最小可用的文件、网络和应用权限是什么？是否能只读或只对当前工作区开放？
3 · 设定审批哪些动作必须停下来请人确认？谁会检查请求？
4 · 明确工作范围目标、排除对象、允许动作和停止条件是否清楚？
5 · 检查执行结果查看实际访问、变更和验证结果；审查发现后由负责的人确认修复。
07

Internet access：网络访问是独立边界

Network access

Internet access（互联网访问）控制执行环境能否连接外部网络。它与 Sandbox（沙箱）里的文件访问范围、Approval（审批）是否要求人工确认，是不同的控制维度。

本机执行与沙箱

按当前平台和设置确认命令是否可联网、访问范围如何限制。需要联网的任务只开放完成任务所需的访问，并留意网络权限可能扩大恶意依赖或远端内容带来的风险。

浏览器、插件与连接器

浏览器、插件、MCP 和应用连接可能各自拥有访问路径；Shell 的网络限制不应被理解为自动覆盖这些连接。逐项核对工具本身的授权和组织策略。

文档范围：Security 栏目里的 Internet access 链接目前指向标注为 “Codex Cloud (Legacy)” 的旧版云端文档。它只说明该旧版云端环境，不能直接代表当前本机 Codex、ChatGPT 工作区或其他云端产品的网络策略。请以当前执行环境的设置与管理员策略为准。

08

组织安全管理：身份、策略与审计

Administration

当目标是保护整个工作区或部署环境时，单个聊天的权限模式不够。管理员还需考虑身份与角色、受管配置、连接和插件控制、审计与合规，以及不同本地或云端执行环境各自的策略。

身份与工作区访问

角色、群组、用户生命周期、访问凭据和服务账号，决定谁能进入工作区并使用哪些管理能力。

受管配置与治理

组织可以下发策略限制可用权限、环境或工具；安全治理和审计资料用于持续监督使用情况与风险。

管理层级：个人审批模式服务于当前操作；设备、环境和工作区管理政策适用于更大范围。云端环境的策略也不能凭本地配置推断，管理员应分别验证生效边界。
