CHATGPT LEARN · WORKFLOWS

让工作持续、可复用、可跟进

Workflows（工作流）栏目汇集了组织长期任务、复用做事方式、生成可交互内容、安排未来工作与跟踪进度的功能。

阅读范围：本页覆盖侧边栏 Workflows 下的八项内容。产品能力会因平台、账户、工作区设置和功能逐步开放而不同；使用前以自己的界面是否出现该功能为准。
01

项目与聊天

Projects and chats

项目（Project）把相关聊天、文件和指令放在一起，让持续工作拥有共享背景；聊天（Chat）则承载某一次具体交流或一个独立结果。

何时使用项目

  • 工作会持续一段时间或产出多个关联结果。
  • 不同聊天需要参考相同资料、文件或背景。
  • 同一项目内可为不同目标开独立聊天，保持每条对话聚焦。

两类项目

  • ChatGPT 项目（ChatGPT project）：在 ChatGPT 中组织项目文件与相关聊天。
  • 本地项目（local project）：连接电脑上的一个或多个文件夹，便于围绕本地文件工作。
判断核心：项目解决“背景和资料要在相关聊天间复用”；独立聊天适合一次完成且不需要共享项目背景的工作。任务是否复杂不是唯一标准。

来源：Projects and chats 官方文档

02

构建插件

Build plugins

插件（Plugin）是可重复使用的任务包，帮助 ChatGPT 以一致方式完成某类工作。插件侧重复用“做事方式”，项目侧重复用“工作背景”。

组成含义例子
App（应用）连接外部服务，读取允许访问的信息或执行支持的操作。从云盘找文档。
Skill（技能）提供完成任务的步骤、规则或格式。按固定结构总结文档。
App + Skill先获取外部资料，再按可复用规则处理。从云盘找两份文件，再按清单比较。

App 和 Skill 可以单独使用，也可以组合。已经上传到聊天的文件通常不需要 App；只有工作流要访问外部服务或在那里执行操作时，才需要相应 App。

1 · 定义任务说明重复做什么，并准备理想结果示例。2 · 描述输入与输出明确提供什么资料、结果给谁看、格式和语气。3 · 加入规则与材料补充模板、参考文件、缺失信息的处理方式。4 · 测试和修改用熟悉案例检查格式、来源和边界，再迭代。

插件创建器（Plugin Creator）可通过对话帮助搭建或编辑插件；官方这套对话式创建流程不要求编写代码。创建后可在新聊天输入 @ 选择插件并使用。先测试再分享；分享与安装是不同步骤，使用者仍需要所需权限和外部应用连接。

权限边界：插件不会自动增加对云盘或其他服务的访问权限。工作区设置、连接授权和用户在源服务中的权限仍然生效。

来源：Build plugins 官方文档

03

可视化

Visualizations

可视化（Visualization）把问题、想法或资料变成图表、地图、示意图、计算器、模拟或可交互解释，适合“看关系、改参数或动手探索”比单看文字更清楚的情况。

需求合适形式
展示结构、关系或步骤示意图 / diagram
呈现数字数据与比较图表 / chart
表达地点或空间分布地图 / map
需要改变输入、时间、运动或空间关系交互式可视化 / interactive visualization
要长期托管、通过链接分享，或保留数据网站 / Site

提出请求时，说明期望结果、来源资料、要回答的问题和有用的交互方式。可在支持的 Chat 或 ChatGPT Work 中用 @Visualize 调用。生成结果通常是创建时信息的快照，不一定会随连接的数据源持续同步；分享前应检查数据、假设、标签与无障碍体验。

可用性：官方文档标注网页端对受支持账户开放，桌面端和移动端处于逐步开放状态；Codex CLI 与 IDE 扩展不支持渲染可视化。界面中是否出现 Visualize 是可用的重要信号。

来源：Visualizations 官方文档

04

计划任务

Scheduled tasks

计划任务（Scheduled task）让任务在预定时间重复运行；在部分支持的账户与平台上，也可以由特定应用事件触发。

按时间运行

例如每天整理摘要、每周生成报告。独立任务每次从已保存的提示开始；聊天内的计划任务则回到原聊天并使用既有上下文。

按事件触发

支持的 Gmail、Slack 或 GitHub 事件可以启动任务。触发条件决定“何时运行”，保存的提示决定“运行时做什么”。事件触发与时间计划不能合并在同一个任务里。

任务可以结合文件、连接的工具、插件或 Skill。网页任务不能直接访问电脑上的文件夹；桌面端本地项目任务需要电脑开机、ChatGPT 应用运行且项目仍在磁盘上。Git 仓库任务可选择在本地项目运行或使用独立 worktree（工作树）隔离改动。

使用建议：先在普通聊天里验证提示词，再创建计划；检查前几次运行并调整范围、工具或频率。后台运行前也要明确权限边界与审阅方式。

来源：Scheduled tasks 官方文档

05

长期任务

Long-running work

对于需要多步完成的工作，明确最终成果、限制条件和完成标准，并在同一聊天中持续补充背景或调整要求。

目标要素写清楚什么例子
结果（Outcome）要交付什么，而非只描述要做的动作。完成并交付迁移后的代码。
限制（Constraints）必须遵循的工具、范围、兼容要求或禁用做法。保留已有行为，使用严格类型。
验证（Verification）哪些检查能证明完成。编译通过、测试通过、满足评审标准。

目标模式（Goal mode）用 /goal 启动，可在工作期间暂停、继续或编辑目标；如果结果还不清楚，可先用 /plan 梳理约束和可衡量的成功标准。相关子任务放在项目中；彼此独立、可并行的任务可分开聊天。

与计划任务的区别：长期任务强调持续推进同一目标并由你随时介入；计划任务强调按时间或事件自动启动。两者都可能持续较久，但“怎样启动、如何维持上下文”不同。

来源：Long-running work 官方文档

06

通知与活动

Notifications

通知（Notification）提醒你有工作需要关注。设置项和送达渠道会随使用界面不同而变化。

系统通知

可设置任务完成时是否提醒，例如始终提醒、应用在后台时提醒或不提醒；权限请求和问题提醒也有单独控制。网页端可按账户设置推送、电子邮件或短信等渠道。

活动视图（Activity view）

侧边栏的铃铛视图集中查看未读、运行中、等待回复的聊天；可筛选 Chat、Work、Pinned 或 Scheduled 等内容。

容易混淆：活动视图是应用内查看聊天状态的地方；系统通知是操作系统或账户渠道发来的提醒。两者相关，但不是同一个控制面板。

来源：Notifications 官方文档

07

宠物助手

Pets

宠物（Pet）是可选的动画伴侣，用于快捷开启聊天和跟踪工作状态。它改变外观与状态呈现，不会改变 ChatGPT 完成任务的方式。

状态含义
Running（运行中）聊天正在工作。
Needs input（需要输入）等待你的批准、回答或决定。
Ready（已完成 / 可查看）任务已完成，有未读活动。
Blocked（受阻）任务失败或遇到系统问题。

桌面端的浮动宠物可以在其他应用上方显示，并跟踪多个聊天；网页端宠物能力较少。通过宠物控件新建的聊天默认不属于任何项目；要使用项目背景，应从主应用里的项目启动聊天。活动托盘与系统通知是分开的。

来源：Pets 官方文档

08

Codex Micro

Codex Micro

Codex Micro是与 ChatGPT 桌面应用配合使用的实体控制器，让你无需离开键盘就能查看、切换聊天、语音输入和触发常用动作。

Agent Keys（代理键）

六个按键可跟踪聊天并用灯光显示状态，也可配置成优先聊天或自定义动作。

Command Keys（命令键）

六个按键可触发常见操作，如切换快速模式、批准或拒绝、继续到新聊天、按住说话和发送消息。

摇杆与旋钮

摇杆可绑定方向动作；旋钮可用于浏览输入栏选项、调整推理力度、滚动聊天或运行自定义动作。

连接与设置

通过 USB-C 或蓝牙连接；在 ChatGPT 桌面应用设置中配置按键、灯光和语音。实际硬件需设备本体，属于可选控制方式。

与通知、宠物的区别：Codex Micro 是硬件快捷控制器；宠物是屏幕上的动画状态伴侣；通知与活动视图用于提醒和查看状态。它们都能帮你跟进任务，但交互方式不同。

来源：Codex Micro 官方文档
