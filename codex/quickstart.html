Where to use ChatGPT

官方列出了哪些使用入口？

Quickstart 介绍 ChatGPT 桌面应用与网页入口，并简述开发者可选的 Codex 使用方式。页面将桌面应用标为适合项目、本地文件和长时间任务的推荐入口；网页入口无需安装，适合在云端处理复杂任务。

桌面应用 · 推荐

用于跨项目、本地文件和长时间任务。

网页

无需安装；可在云端连续处理复杂任务。

开发者入口

在终端或代码编辑器中使用 Codex；远程编码可创建 Codex Cloud 环境。

本节要点

官方文档按任务场景区分入口：本地项目和文件侧重桌面应用；网页适合免安装的云端工作；开发者可继续查看 CLI、IDE 扩展或 Cloud 的专门说明。

Setup

桌面端和网页端的设置步骤。

官方 Quickstart 分别列出桌面端与网页端的开始方式。桌面端的流程还包括选择要让 ChatGPT 工作的位置，并在软件开发任务中切换到 Codex。

  1. 1
    桌面端：安装并登录

    下载 macOS、Windows 或 Linux 对应的 ChatGPT 桌面应用，打开后使用 ChatGPT 账号登录。

  2. 2
    桌面端：选择工作位置

    开始聊天、创建项目或打开文件夹。官方说明：ChatGPT 可以读取和修改所选文件夹中的文件。

  3. 3
    桌面端：开始聊天

    按任务类型选择 ChatGPT Work、Codex 或 ChatGPT Chat；官方给出的对应场景见下一节。

  4. 4
    网页端：登录并开始

    打开 ChatGPT 网页并登录；选择 Chat 进行对话，选择 Work 进行研究、分析和制作交付物，然后开始聊天或选择项目。

官方页面注明，也可以使用 API key，但部分功能可能不可用。

Start a chat

按任务场景选择 ChatGPT Work、Codex 或 ChatGPT Chat。

Quickstart 在桌面端的“Start a chat”步骤中区分了三种入口。判断依据是当前任务属于交付型工作、软件开发，还是轻量对话。

ChatGPT Work

用于研究、分析，或制作文档、演示文稿、电子表格、Sites 等交付物。桌面端从 ChatGPT 进入，再在新聊天页上方切换到 Work。

Codex

用于需要代码库上下文和开发工具的软件开发任务。在 ChatGPT 下拉菜单中选择 Codex。

ChatGPT Chat

用于快速问题、探索想法或围绕主题进行对话。桌面端从 ChatGPT 进入，再在新聊天页上方切换到 Chat。

官方补充

在 Codex 中也可以发起普通快速聊天：将指针移到 New chat 旁，选择右侧的 Quick chat 图标。网页端的 Quickstart 则将 Chat 描述为问答、探索想法和对话，将 Work 描述为研究、分析和制作成果。

Send your first message

描述目标，并提供需要的文件或上下文。

官方 Quickstart 对首条消息的说明是：描述你的目标，并添加 ChatGPT 需要的文件或上下文。页面给出的示例入口包括准备决策、分析电子表格和改进应用。

Prepare a decision

准备一项决策。

Analyze spreadsheets

分析电子表格。

Improve this app

改进这个应用。

我的理解

首条消息提供任务目标；文件和上下文为任务补足材料。官方 Quickstart 在此处给出的是示例任务入口，并没有规定统一的提示词模板。

Use ChatGPT

从一个问题开始，补充上下文，再逐步完善结果。

官方页面把使用过程概括为自然语言协作：从问题、想法、粗略笔记、文件或待办任务开始；让 ChatGPT 解释、构思、起草、研究、分析或创作；提供所需上下文和工具；检查结果并继续校准。

  1. 1
    提出一个起点

    可以是问题、想法、初步笔记、文件，或需要完成的任务。

  2. 2
    说明希望它做什么

    例如解释信息、发展想法、起草内容、研究主题、分析材料或创作新内容。

  3. 3
    补充相关上下文与工具

    可加入文件、网页搜索、项目或插件等任务需要的材料和能力。

  4. 4
    审阅并继续调整

    查看结果、纠正方向并要求修改；官方说明，不需要一开始就写出完美提示词，也不需要特殊命令。

入口选择

Chat 适合问答、搜索、头脑风暴、草拟或比较；Work 适合有明确结果、需要可审阅交付物的任务；Codex 适合开发工具和技术细节，尤其是软件开发。

Get started with Work

把有明确结果的较大任务交给 Work。

官方将 ChatGPT Work 描述为委派实际工作的方式：它可以利用文件、插件和获准使用的工具收集信息、生成成品文件、运行工作流，并把结果留给用户审阅。过程中可以查看进展、回答问题、调整方向，并批准重要操作。

制作演示文稿

把笔记、文档、研究或会议材料整理成结构化演示文稿。

研究与分析

查阅来源或文件、比较信息，再形成可供审阅的分析结果。

完成可交付任务

准备简报、计划、周期性更新、工作流或其他完成后的文件。

  1. 1
    切换到 Work

    然后选择要完成的任务。

  2. 2
    给出清晰结果、少量来源材料和可审阅的产物

    这是官方列出的适合尝试的任务特征。

  3. 3
    跟进执行过程并审阅结果

    可以回答过程中出现的问题、改变方向，并在重要操作前作出批准。

桌面应用中的 Work 在功能可用时也能使用本地文件、应用和浏览器。官方页面还区分本地与云端工作环境；具体能力取决于可用功能和工作区设置。

Meet dots

让 dot 持续跟进跨对话的责任与变化。

官方将 dot 描述为常驻云端的 agent：它可以在对话之间持续推进工作，利用相关对话、偏好和保存的笔记跟踪进展，并在需要用户判断时带回结果或提出问题。它适合需要持续留意、随变化更新并主动跟进的责任。

持续跟进

例如跟踪活动筹备中的决定、截止日期和待回复事项，并在预算或期限出现风险时提醒。

连接工作渠道

可在 ChatGPT、Slack 或 Teams 与同一个 dot 对话；连接渠道本身不会自动开放邮箱、本地电脑或其他应用。

协作完成任务

dot 可把需要交付的工作委派给 ChatGPT Work 或 Codex，再持续跟进进度。

与其他入口的区别

Chat 用于即时问答和构思；Work 用于委派研究、分析或文件制作；Codex 用于软件开发；dot 则负责持续跟踪一项责任，在变化时推进并跟进。登录、连接电脑或应用时仍受各自权限与确认机制约束。

官方说明 dots 正分批开放，是否可用取决于账号、地区和工作区条件；可用性以当前官方页面与账户界面为准。

Import from another agent

把受支持的设置和近期工作带入 ChatGPT 或 Codex。

官方导入流程可以迁移指令、设置、Skills、Plugins、项目和近期工作。桌面应用支持从 Claude Code、Claude Cowork 或 Cursor 导入；Codex CLI 支持从 Claude Code 或 Cursor 导入。

导入边界

官方说明导入不会更改或删除原有 agent 设置。导入后，部分插件或连接仍可能需要授权和后续配置；迁移内容应在依赖它们之前检查。

  1. 1
    桌面应用中导入

    打开 Settings → Import；若没有 Import 栏目，则到 General 找到 Import other agent setup。

  2. 2
    选择来源和要迁移的项目

    选择 agent，再选择要导入的设置、项目文件和近期聊天，完成后打开导入的项目或聊天继续工作。

  3. 3
    完成尚未配置的连接

    如果插件或连接需要授权，按状态提示完成登录或配置；也可以在设置中开启自动更新，让导入内容与原 agent 保持同步。

  4. 4
    Codex CLI 中导入

    启动本地 Codex CLI，输入 /import，选择 Claude Code 或 Cursor，再选择要导入的设置、项目文件和近期聊天。

Codex CLI 的导入范围和使用限制以官方文档为准；文档目前说明最多导入最近 30 天内的 50 个聊天，且运行任务期间、远程会话中或连接本地 app-server daemon 时不可使用 `/import`。
