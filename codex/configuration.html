CHATGPT LEARN · CONFIGURATION

把默认习惯、项目规则和工具连接放对位置

Configuration（配置）栏目介绍如何让 ChatGPT 与 Codex 开发工具按你的偏好和项目要求工作。本页重点讲解其中的 Codex 配置概念，并区分个人设置、项目指导、组织约束与可扩展能力。

阅读范围：官方 Configuration 是一个文档栏目，不是单一开关。本页是概念地图；具体可用设置会随产品表面、平台、版本和组织管理策略变化。
01

先把配置分成几层

Configuration map

遇到“希望它以后都这样做”时，先判断这条信息应该在哪一层生效：个人默认、项目指导、当前任务，还是管理员施加的边界。

行为与上下文

  • 个性化 / Memories：个人偏好与有用背景。
  • AGENTS.md / Rules：项目或目录相关的持久指导。
  • 当前提示：本次任务目标、材料和临时要求。

设置与能力

  • config.toml：Codex 的模型、权限及工具等默认设置。
  • Skills / MCP / Subagents：复用流程、连接外部工具、拆分专门工作。
  • requirements.toml：组织可施加的强制限制。
核心区别：配置文件设定默认行为；项目指导告诉 Codex 如何在该代码库工作；requirements 是管理员边界，可限制用户设置。它们互相配合，不能互相替代。
02

个人默认与项目配置

config.toml

Codex 的主要配置文件使用 TOML 格式，常见的个人配置位置是 ~/.codex/config.toml；可信任项目可以在仓库内提供 .codex/config.toml，为此项目设置覆盖值。

层用途何时适合
命令行覆盖针对一次启动临时改值。试用某个模型或参数，不想永久改默认值。
项目配置项目内的 Codex 设置；只有信任项目时才加载。该仓库需要特定模型、工具或验证方式。
个人配置当前用户在本机的默认设置。希望多个项目共用相同的默认偏好。
系统 / 管理配置设备或组织提供的设置与限制。由组织统一管理的环境。

官方列出的优先顺序包括命令行与显式覆盖、可信项目配置、配置档案、用户配置、云端默认值、系统配置，最后才是内置默认值。管理员的 requirements 会约束可选行为；它们不是普通的“更高优先级默认值”。

03

AGENTS.md 与 Rules：让规则在合适范围生效

Project guidance

AGENTS.md 是 Codex 开始工作前读取的持久项目指导文件。它适合记录项目约定、常用验证方式、目录说明和代码审查要求。

AGENTS.md

可以放在仓库根目录，也可放在更具体的子目录，让指导贴近相关代码。适合团队共享、随仓库版本管理的项目规则。保持内容精简，把重复出现的纠正经验沉淀进去。

Rules

用于更聚焦的行为规则，适合在特定条件或工作环境下约束 Codex。官方 Configuration 将 Rules 与项目指导、配置文件分别列出；不要把每条指令都塞进一个巨型文件。

范围选择：个人沟通偏好放全局；团队共同遵守的仓库规则放项目指导；只对本次工作成立的内容写在提示里。具体文件发现和规则应用以当前官方文档为准。

来源：Custom instructions with AGENTS.md ↗ · Customization ↗

04

记忆、电脑历史与项目指令不是同一种东西

Memories & history
功能保存什么与项目指导的区别
Memories（记忆）跨聊天有帮助的偏好、背景或经验。帮助个性化与延续上下文；不应当作必须执行的仓库规范。
Computer History（电脑历史）在支持的平台与设置下，保存电脑活动的上下文。帮助找回近期工作线索，不是项目配置文件，也不是指令层。
AGENTS.md针对项目或目录的明确工作约定。提供可审阅、可共享的持久指导，不是个人回忆录。

记忆和历史可管理或关闭；可用性因产品而异。不要把敏感信息当作长期上下文保存。来源：Customization overview ↗。

05

Skills、MCP 与 Subagents：分别扩展方法、连接和分工

Extend Codex

Skill（技能）

把重复任务的做法、要求和参考资料组织成可复用流程。它回答“这类工作按什么步骤完成”。

MCP（模型上下文协议）

让 Codex 连接外部工具或数据服务。它回答“可以使用哪些外部工具与信息”。连接和授权范围仍需审阅。

Subagent（子代理）

把适合并行或需要专门关注的子任务交由独立代理处理，再汇总结果。它回答“如何分配工作”。

Hooks / Record & Replay

Hooks 可在特定事件触发自动化命令；Record & Replay 记录与重放支持的交互流程。两者属于更进阶配置，按官方文档和环境支持情况使用。

相似功能对照：Skill 管可复用方法，MCP 管外部连接，Subagent 管任务分工，Hook 管事件触发动作。

06

配置默认值不能越过组织边界

Managed requirements

Codex 权限由配置值、运行环境和组织要求共同决定。管理员可以在受管设备或工作区施加 requirements.toml 限制，例如禁止某些审批策略或沙箱选项。

沙箱（Sandbox）

定义本地文件和网络等资源的访问边界。

审批策略（Approval policy）

定义何时允许继续、何时暂停等待审批。审批策略和沙箱是相关但不同的控制。

理解优先级：用户配置可以给出默认值；管理员要求可以禁止某些选择。界面里看不到某个选项时，不能仅靠本地配置假定它已生效。

来源：Configuration Reference ↗ · Permissions ↗

07

注意平台范围：本页讲的是 Codex 配置概念

Platform scope

Configuration 栏目还包含 Linux、Windows、WSL、桌面应用和开发工具等平台主题。某项设置可能只适用于 CLI、IDE 扩展或桌面端中的一部分。ChatGPT Work 的聊天偏好、桌面应用设置以及本地 Codex 的 config.toml 不应混为一谈；实际操作前请打开对应平台的官方页面核对。

本页依据官方页面整理概念，不是完整配置键清单。具体配置项、默认值和系统要求以官方参考文档为准。
