01 · Match features to your goal

从要解决的问题反推扩展机制。

机制解决的问题典型场景
CLAUDE.md每次会话都需要同一背景“使用 pnpm”“提交前运行测试”
Skill复用知识、清单或流程/review 执行团队审查清单
Subagent隔离上下文或委派专项工作大量搜索后只带回结论
MCP连接外部数据与工具查询数据库、操作浏览器、读取工单
Hook在事件中确定执行脚本编辑后自动格式化，阻止危险写入
Plugin打包和分发一组扩展跨仓库安装 Skills、Hooks、MCP 等
选择顺序

先用内置工具和清晰提示完成工作；重复出现的长期约定放 CLAUDE.md，重复流程做 Skill。只有需要隔离、外部连接、确定自动化或分发时，再引入其他层。

02 · Skills

把反复粘贴的流程，变成按需加载的能力。

Skill 以 SKILL.md 描述知识和操作步骤。Claude 可根据描述自动选择，也可由你输入 /skill-name 显式调用。正文只在使用时加载，适合较长参考资料和多步流程。

.claude/skills/review-page/SKILL.md
---
name: review-page
description: Review a static course page for links, mobile layout, and source accuracy
disable-model-invocation: true
---
Review the requested page. Check:
1. Internal links and anchors resolve.
2. The 390px layout has no global horizontal overflow.
3. Commands match the linked official sources.
4. Report only actionable findings with file locations.

disable-model-invocation: true 让它只由你手动调用，适合发布、部署等有副作用或必须明确触发的流程，也避免描述占用启动上下文。自定义 commands 已合并到 Skills；旧 .claude/commands/ 仍可用，新流程优先使用 Skills。

03 · Subagents

把大量调查或专项审查放进独立上下文。

Subagent 是独立工作的 agent：拥有自己的上下文和可用工具，完成后把摘要带回主会话。Skills 提供“做什么与怎么做”，Subagent 提供“由谁在独立环境中做”，两者可以组合。

适合委派

大范围只读调查、日志分析、独立代码审查、可清晰划分的并行子任务。

限制工具

自定义 agent 只授予职责需要的工具；只读审查不必默认获得写入权限。

核对结果

独立上下文减少偏见，但审查者仍可能误报。要求引用文件证据并聚焦真实要求。

使用 /agents 查看和创建自定义 subagents；项目级定义放在 .claude/agents/。后台运行和当前任务可用 /tasks 查看。

04 · Model Context Protocol

MCP 负责连接，Skill 可以教会 Claude 如何用好连接。

MCP server 提供内置工具之外的数据与行动能力，例如查询 issue tracker、数据库或控制浏览器。官方入门用无需认证的 Claude Code 文档 server 演示完整连接流程。

在 shell 中添加并验证官方文档 MCP server
claude mcp add --transport http claude-code-docs https://code.claude.com/docs/mcp
claude mcp list
  1. 1
    添加后检查状态

    “Added”表示配置写入，不等于工具已连接。claude mcp list 或会话内 /mcp 才能验证。

  2. 2
    理解作用域

    默认 local 仅你且仅当前项目；user 是你的所有项目；project 写入根目录 .mcp.json 供团队共享。

  3. 3
    审批与保密

    首次工具调用可能需要许可。团队 server 也需成员批准；凭据用安全的环境变量或认证流程，不写进共享配置。

  4. 4
    不用时移除

    claude mcp remove claude-code-docs。server 名称、说明与工具定义也会消耗上下文。

该练习会真实修改你的 MCP 配置并连接外部服务。只在理解来源和权限后执行；本网站不会在后台替你运行。

05 · Hooks

必须每次发生的事，用确定性脚本。

Hooks 在工具调用、编辑、通知、停止等生命周期事件中运行外部命令。与 CLAUDE.md 的模型引导不同，Hook 不需要模型“记得”执行，因此适合格式化、lint、日志、通知和硬性阻断。

编辑后检查

文件编辑后自动运行格式化器或项目 lint，把结果返回给 Claude。

操作前保护

PreToolUse 可检查即将执行的动作，阻止写入受保护目录或不符合规则的命令。

完成前验证

Stop Hook 可运行确定检查并阻止结束；官方说明连续阻止存在上限，不是无限循环。

提醒与通知

Claude 等待权限或输入时，发送系统通知，减少长任务中的守候。

可用 /hooks 查看与配置，或写入 settings JSON。Hook 本身是会执行的代码：审查命令、输入转义、超时、失败行为与权限，不把不可信文本直接拼进 shell。

06 · Plugins

需要分享一整套能力时，再打包成插件。

Plugin 可以把 Skills、Hooks、Subagents、MCP servers 等组合为可安装单元，通过 marketplace 分发。Plugin skills 使用命名空间，例如 /my-plugin:review，减少同名冲突。

先找已有能力

用 /plugin 浏览市场。若只要单个流程， standalone Skill 往往更轻。

安装前审查

查看发布者、源码、包含的 Hooks、MCP、命令和所需权限；插件不是纯文本收藏。

移除后验证

确认配置、外部连接和后续进程都已处理；组织可通过 managed settings 控制可用市场与插件。

第三方插件和 MCP 都可能引入代码执行、数据访问或外部副作用。“能安装”不等于“值得信任”。

07 · Context costs

每个扩展都在改变 Claude 看到的世界。

机制何时加载上下文特点
CLAUDE.md会话启动及嵌套发现全文进入相关会话，保持精简。
Skills启动时描述，使用时正文按需成本低；手动专用 Skill 可不加载描述。
MCP会话启动连接工具名称、说明与 schema 有成本；tool search 可延期部分定义。
Subagents委派时独立上下文，主会话主要接收摘要。
Hooks事件触发脚本在外部运行；返回内容仍可能进入上下文。

08 · 实战练习

只做一个小而完整的 Skill。

  1. 找出你最近重复过三次的一段检查流程，先写成普通提示并验证结果。
  2. 在练习项目创建 .claude/skills/review-page/SKILL.md，使用上面的精简示例并调整任务。
  3. 保留手动调用设置，运行 /review-page 检查一页真实结果。
  4. 核对它是否按步骤执行、是否给出文件证据，再删减无效说明。
  5. 只有确实需要外部数据或强制自动化时，才继续尝试 MCP 或 Hook。
完成标准你能说清为什么选 Skill 而不是 CLAUDE.md、Subagent 或 Hook；新 Skill 能完成一次真实检查，且没有引入不必要的外部权限。
