01 · The agentic loop

不是一次回答，而是循环推进。

收到任务后，Claude 会在“收集上下文—采取行动—验证结果”之间反复切换。一次代码库问答可能只需要探索；修复 bug 则可能经历多轮错误复现、修改和测试。

收集上下文

搜索相关文件、阅读实现与配置、运行测试获得真实错误，而不是先猜根因。

采取行动

根据新信息修改一个或多个文件、执行命令，并在过程中调整下一步。

验证结果

重跑测试或构建，读取结果并继续迭代。你提供可检查的完成条件，闭环才可靠。

你也在循环里

Claude 可以自主串联多步操作，但你可以随时中断、补充信息或改变方向。自主不等于不可 steering，也不等于结果无需审查。

02 · Models + tools

模型决定下一步，工具把决定变成行动。

Claude Code 是围绕模型运行的 agentic harness：提供工具、上下文管理和执行环境。模型理解代码与任务；工具调用的结果再次进入循环，影响后续判断。

工具类别典型行动任务中的角色
文件操作读、写、编辑、重组文件理解并实现跨文件修改
搜索按名称或内容定位代码找到相关模块和调用关系
执行Shell、测试、构建、Git复现问题并验证结果
Web搜索和读取资料核对文档或错误信息
代码智能符号导航、类型诊断精确理解引用与编辑后的错误；需相应插件

日常使用 Sonnet 可覆盖多数编码任务，复杂架构决策可考虑更强的 Opus。用 /model 或启动时的 --model 选择；具体模型名称和可用性以账户与官方文档为准。

03 · Execution environments

界面可以改变，代码在哪里运行必须清楚。

Local

代码和命令在你的机器执行，可访问本地文件、工具与开发环境；权限边界尤其重要。

Cloud

任务在 Anthropic 管理的虚拟机中运行，适合卸载长任务或处理本地未检出的仓库。

Remote Control

从浏览器或手机控制仍在本地机器运行的会话；并不是把执行迁到云端。

共同核心

CLI、IDE、Desktop、Web 等界面改变的是交互方式，底层 agentic loop 相同。项目指令、工具和具体配置能否带入，要看执行环境与平台文档。

04 · Context window

上下文是工作记忆，也是有限资源。

对话、文件内容、命令输出、CLAUDE.md、Skills 和系统指令都会占用上下文。随着内容增加，早期细节可能丢失，无关信息也会增加噪声。

操作何时使用结果
/context想知道空间花在哪里查看当前上下文分类占用与优化建议。
/compact [重点]同一任务还要延续，但历史太长用摘要替换历史，可指定保留重点。
/clear切换到无关任务，或多次纠正后重新开始清空当前上下文；原会话已保存且可恢复。
/memory想核对项目记忆查看启动了哪些 CLAUDE.md 与 auto memory 文件。
长期规则放 CLAUDE.md

不要只依赖会话早先的一句话。压缩后某些对话细节会消失，持久项目指令应在合适文件中。

大范围调查考虑 Subagent

子 agent 在独立上下文中读取大量资料，只把摘要带回主会话，减少主任务噪声。

上下文窗口图示中的 token 数是教学示例，不是你的实际用量。用 /context 查看真实会话；MCP、Skills 和规则的加载行为以当前版本文档为准。

05 · Sessions

继续原会话，或从同一点分出新路线。

CLI 会话保存在本地并关联项目目录。继续会话会沿用同一会话 ID；分支则复制目前对话并切换到新 ID，让原路线保持不变。

恢复与分支
claude --continue
claude --resume
claude --resume auth-refactor
claude --continue --fork-session
/rename

尽早给独立任务命名，例如 /rename auth-refactor，以后更容易找到。

/branch

从当前对话创建分支，适合比较另一种实现，不影响原会话。

/resume

在会话内切换历史对话；选择器支持搜索、预览和按项目或 worktree 扩大范围。

恢复或分支不会继承“仅限本次会话”的权限批准。不要在两个终端同时写同一会话；需要并行时先 fork，避免消息交错。

06 · Checkpoints

局部撤销很有用，但它不是 Git。

每条用户提示会创建检查点，Claude 的直接文件编辑工具会在修改前捕获代码状态。按 Esc 两次或运行 /rewind，可恢复代码、对话或两者，也可从选定点开始摘要。

能恢复

当前会话中由 Claude 文件编辑工具产生的变更；检查点可跨恢复的会话使用。

不能当作通用撤销

Bash 命令产生的文件修改、外部进程或其他会话的变化通常不被跟踪。

仍需版本控制

Git 负责长期历史、协作和可靠版本；检查点只是会话级恢复安全网。

外部系统副作用——部署、数据库变更、远端推送——不能因为存在检查点就视为可撤销。

07 · 实战练习

观察一次完整的 agentic loop。

  1. 给 Claude 一个已知的小测试失败，要求先复现、定位、修复再验证。
  2. 记录它每个阶段读取的证据和工具调用，标注 gather、act、verify。
  3. 运行 /context 查看上下文；再用 /rename concept-practice 命名会话。
  4. 退出后用 claude --resume concept-practice 恢复，确认历史仍在。
  5. 如果有实验性编辑，使用 /rewind 查看可恢复选项；同时检查 Git diff，比较两种安全网。
完成标准你能解释工具结果如何影响下一步，知道何时 /clear、/compact、fork 或 rewind，并能说出检查点无法覆盖的两类变化。
