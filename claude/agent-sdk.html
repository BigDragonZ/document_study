01 · CLI or SDK

日常开发用 Claude Code，产品自动化用 Agent SDK。

如果你只是要在终端修 bug、写测试或审查代码，交互式 CLI 更直接。如果需要把 agent 嵌入自己的服务、批处理、审批界面或数据流水线，SDK 提供消息对象、工具回调、结构化输出和生命周期控制。

CLI -p

最简单的脚本与 CI 入口，通过参数、管道和 JSON 输出组合。

Python SDK

使用 async iterator、ClaudeAgentOptions 和 Python 消息类型构建异步应用。

TypeScript SDK

使用 query、options 和 TypeScript 消息对象集成 Node.js 应用。

不是只生成文本

SDK 中的 Claude 能直接调用文件、命令和自定义工具。你要像设计真实软件执行环境一样设计权限、错误处理和验证。

02 · Setup

选择语言，安装对应 SDK。

官方 Quickstart 要求 Node.js 18+ 或 Python 3.10+，并使用 Anthropic Console 的 API key 或受支持的云提供商认证。下面的安装命令应在你的独立练习项目中执行，不是本站依赖。

TypeScript / Python
npm install @anthropic-ai/claude-agent-sdk

python3 -m venv .venv
source .venv/bin/activate
pip install claude-agent-sdk

在 .env 或 shell 环境配置 ANTHROPIC_API_KEY，并确保秘密文件不进入版本控制。TypeScript SDK 通过 optional dependency 携带对应平台的原生 Claude Code binary，无需另行安装 CLI；其他环境和提供商要求见官方。

不要在自己的产品中把 claude.ai 登录或订阅速率限制当成通用 API 认证。按 SDK 官方要求使用 API key 或第三方提供商。

03 · Your first agent

先构建一个只读代码库分析器。

query 创建 agentic loop 并返回异步消息流。下面的教学示例只允许读取、搜索和列文件，并用 dontAsk 拒绝其他需要审批的动作；它比一开始就自动编辑更适合第一次实验。

agent.py · 只读教学示例
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, AssistantMessage, ResultMessage

async def main():
    async for message in query(
        prompt="Read this project and report its test commands. Do not edit files.",
        options=ClaudeAgentOptions(
            allowed_tools=["Read", "Glob", "Grep"],
            permission_mode="dontAsk",
        ),
    ):
        if isinstance(message, AssistantMessage):
            for block in message.content:
                if hasattr(block, "text"):
                    print(block.text)
        elif isinstance(message, ResultMessage):
            print(f"Done: {message.subtype}")

asyncio.run(main())

在激活的虚拟环境中运行 python agent.py。TypeScript 使用 import { query } from "@anthropic-ai/claude-agent-sdk" 和 for await，options 字段采用 camelCase，例如 allowedTools 与 permissionMode。

消息循环

每次迭代可能得到助手消息、工具事件或最终结果。SDK 负责工具执行、上下文管理和重试；你的代码负责处理消息、错误、输出和产品逻辑。

04 · Sessions + structured output

需要多轮就保留会话，需要程序消费就定义结构。

Sessions

通过 continue、resume 或 fork 延续和分支上下文。明确会话存在哪里、保留多久，以及多实例部署如何共享。

Structured output

用 JSON Schema 约束最终结果，程序读取结构化字段而不是依赖脆弱的自然语言解析。

Streaming

实时产品可逐条处理消息；后台任务可收集结果。选择输入模式时考虑持续用户消息和取消。

Observability

记录结果、用量、错误、工具调用和追踪信息，让生产问题可以定位，而不是只有最后一段文本。

CLI -p 也支持 --json-schema；SDK 则可以把结构化输出与消息处理、审批回调、工具和持久化组合起来。

05 · Custom tools + MCP

让你的应用提供真正需要的领域能力。

SDK 可以通过 in-process MCP server 暴露自定义函数，也能连接外部 MCP servers。工具名称、输入 schema、权限和返回内容都会成为 agent 接口的一部分。

  1. 1
    设计窄接口

    例如 query_order 比 execute_any_sql 更安全、更容易验证，也更不容易被滥用。

  2. 2
    验证所有输入

    不要信任模型生成的参数；在工具实现中检查类型、范围、授权和业务约束。

  3. 3
    控制返回内容

    只返回任务需要的数据，避免秘密与超大结果进入上下文；外部内容仍可能含提示注入。

  4. 4
    处理副作用

    读写分离，重要动作提供独立审批和审计；不要因函数由代码编写就跳过权限。

06 · Permissions + user input

把审批变成产品流程，而不是卡住的后台任务。

SDK 支持 permission modes、allow/deny 规则、Hooks 和 canUseTool 等审批机制。Default 模式下需要你的应用处理批准请求；dontAsk 则拒绝未预批准的动作，适合锁定自动化。

最小工具

先只读，再按真实需求增加 Edit、Bash 或网络，不把全套权限作为默认模板。

用户审批

把请求、工具参数和风险呈现在 UI 中，将用户决定安全地返回 SDK。

无人值守

设置工具白名单、资源限制、超时、输出验证和明确失败行为，不依赖人工临时救场。

Auto 模式在 SDK 的语言与提供商支持上可能不同；bypassPermissions 只适用于充分隔离且可信的环境。以 Agent SDK Permissions 当前文档为准。

07 · Production

部署的是执行环境，不只是一个 API 调用。

  1. 隔离每个任务或租户的文件系统、进程、网络与凭据，防止跨用户访问。
  2. 使用最小权限 API key 和短期凭据，安全注入，不写进镜像、源码或日志。
  3. 设置并发、turns、预算、超时和资源上限，处理取消与子进程清理。
  4. 设计会话持久化与恢复，理解容器重启后本地状态是否还在。
  5. 用 OpenTelemetry、结构化日志和成本指标观察工具调用与失败。
  6. 对外部输入、工具结果和最终动作保留安全检查与人工审批。
  7. 用真实端到端任务验证结果，不只做 import 或“服务能启动”的检查。

08 · 实战练习

从零运行一个只读 agent。

  1. 在独立练习目录创建虚拟环境并安装所选 SDK；本网站项目不需要也不应安装这些依赖。
  2. 准备一个小型示例代码库和 API key，确保目录没有秘密或重要未提交工作。
  3. 使用上面的只读 Python 示例，运行并观察 Read/Glob/Grep 工具事件。
  4. 让输出列出测试命令，逐项对照仓库验证；再加入 JSON Schema 约束输出。
  5. 尝试恢复会话，最后记录工具、权限、错误处理和部署前仍缺少的保护。
完成标准agent 在只读边界内完成一次真实代码库分析，结果可验证且凭据未写入源码；你能解释增加写权限前必须补上哪些审批和验证。
