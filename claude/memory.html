01 · Two memory systems

你写的指令，与 Claude 自动积累的笔记。

每个新会话都有新的上下文窗口。CLAUDE.md 与 auto memory 把知识带到下一次会话，但作者、内容和管理方式不同。

对比项CLAUDE.mdAuto memory
谁编写你或团队Claude 根据协作自动记录
适合内容项目约定、命令、工作流、架构偏好、纠正、无法直接从代码看出的模式
加载方式按位置与作用域在会话中加载每会话加载 MEMORY.md 前 200 行或 25KB，以先达到者为准
管理方法像代码一样审查、精简、版本管理检查 Claude 记录的内容，必要时纠正
两者都是提供给模型的上下文，不是强制安全策略。必须无条件阻止的动作，应使用权限 deny 规则或合适的 PreToolUse Hook。

02 · Write effective instructions

只写“删掉就会出错”的内容。

当同一纠正出现第二次、代码审查反复发现同类遗漏，或新成员每次都需要相同背景时，就适合把它沉淀为项目指令。用 /init 可以分析项目并生成初稿，但你要核对准确性。

应该保留

真实启动/测试命令、区别于默认习惯的代码风格、非显而易见的架构决定、仓库协作约定。

应该移走

从代码就能看出的逐文件介绍、经常变化的信息、长篇 API 教程、偶尔使用的完整流程。

如何表述

具体、简短、可执行。说明命令和验证方式，不写“写干净代码”这类无法检查的空话。

CLAUDE.md · 精简示例
# Project commands
- Preview: python3 -m http.server 8000
- No dependency installation or build step.

# Conventions
- Keep the existing HTML/CSS/JavaScript structure.
- Preserve mobile layouts and official source links.
- Check internal links and copy interactions after page changes.

可用 @path/to/file 引用额外材料，例如 @README.md。引用也会进入上下文，所以应指向稳定、必要的资料，而不是把整库导入。

03 · Scope

规则放在哪里，决定它影响谁。

位置适用范围典型用途
组织 managed policy组织管理的设备与项目统一政策和组织级约定
~/.claude/CLAUDE.md你在本机的所有项目个人长期偏好
项目根目录 CLAUDE.md该项目及协作者可提交的共享项目说明
CLAUDE.local.md你在单个项目中的个人说明个人覆盖；应自行加入 .gitignore
父级与子目录monorepo 的不同层级父级提供共同背景，子目录按需补充

Claude Code 也能读取仓库已有的 AGENTS.md 作为项目指令的替代来源，适合与其他编码 agent 共享约定。本手册仍以 Claude 原生的 CLAUDE.md 为主要教学入口。

不是简单覆盖

多层 CLAUDE.md 会叠加进入上下文。冲突时更具体的指令通常更有影响力，但不要把关键团队规则建立在含糊冲突上；应主动整理。

04 · Path-scoped rules

只和某类文件有关的规则，不必每次加载。

.claude/rules/ 可保存带路径范围的规则。当任务涉及匹配文件时再提供相应指导，适合 monorepo 包约定、迁移目录保护或特定语言的测试习惯。

CLAUDE.md

每次会话都需要知道的短小项目事实与共同约定。

.claude/rules/

只有处理特定路径或文件类型时才相关的规则。

Skill

按需加载的参考资料，或能通过 /<name> 调用的完整工作流。

Hook

在生命周期事件中确定执行的脚本，用于必须发生的检查或动作。

规则的具体 frontmatter、匹配语法和加载时机请直接对照 Memory 官方页面；不要凭其他工具的 rules 格式猜测。

05 · Auto memory

让 Claude 从纠正中学习，但仍要检查笔记。

auto memory 按仓库保存，可跨 worktrees 共享。它适合记录你的偏好、反复出现的纠正和项目上下文，减少下次重新解释。它与 CLAUDE.md 互补，不应悄悄替代团队明确审查过的规则。

  1. 1
    在真实协作中纠正

    清楚说明偏好的命令、目录边界或交付方式，让 Claude 有可学习的稳定模式。

  2. 2
    核对加载内容

    用 /memory 查看相关记忆文件，确认没有过时、错误或敏感内容。

  3. 3
    团队规则显式化

    需要全团队共同遵守的约定，仍写入可审查、可版本管理的 CLAUDE.md。

06 · Troubleshoot

规则没被遵守，先找加载与表述问题。

  1. 用 /memory 或 /context 核对文件是否真的进入当前上下文。
  2. 检查它是否位于正确目录；嵌套说明可能只有在访问相关文件后才加载。
  3. 检查长文件是否淹没重点，删除显而易见和已经无需强调的内容。
  4. 如果规则只在早期对话里说过，压缩后可能消失；移到持久文件。
  5. 如果必须强制生效，不要把 CLAUDE.md 当权限系统；改用 deny 或 Hook。

07 · 实战练习

为你的项目写一页真正有用的记忆。

  1. 在一个练习项目运行 /init，保存生成前的已有 CLAUDE.md，避免覆盖团队内容。
  2. 逐行审查草案：标记项目事实、长期约定、单次任务和显而易见的内容。
  3. 删除后两类，把单次任务移回对话，把偶尔使用的长流程考虑为 Skill。
  4. 运行 /memory 核对加载，再提出一个需要遵守这些约定的真实小任务。
  5. 观察行为并修剪规则；记录哪些内容确实改变了结果。
完成标准项目说明简短、事实准确、命令可运行；你能解释每条为什么必须在每次会话出现，并知道强制限制应放在哪里。
