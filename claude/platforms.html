01 · Compare surfaces

按工作方式选择，而不是寻找“最强入口”。

平台最适合关键特点
CLI终端工作、脚本、远程服务器功能完整，支持 Agent SDK 与自动化
Desktop可视化审查、并行本地会话Diff viewer、应用预览、图形化管理
VS Code不离开编辑器Inline diff、集成终端、文件上下文
JetBrainsIntelliJ、PyCharm、WebStorm 等Diff viewer、选区共享、终端会话
Web长任务、离线后继续Anthropic 管理的云端环境
Mobile外出时启动、监控和调整云会话，或经 Remote Control 接入本地
可以混用

同一个项目可以在不同平台使用。各本地界面可共享项目记忆、配置和 MCP；云端是否能获得这些配置取决于仓库和环境，不要默认本机状态会全部跟随。

02 · Local workflows

本地平台的核心差异是交互与可视化。

CLI

适合熟悉终端、需要脚本组合、Agent SDK、完整命令与第三方提供商支持的场景。

Desktop

适合同时管理多个本地会话、查看 diff、运行应用预览，以及不想直接操作终端的用户。

IDE

适合把已打开文件、选区和代码修改放在同一工作流；具体能力随 VS Code 与 JetBrains 而异。

Desktop 的并行会话可用 Git 隔离，提供文件编辑、终端、可视化 diff 和应用预览。Computer use、Dispatch 等功能可能有操作系统与 Pro/Max 套餐限制。

界面功能更新很快。安装或依赖某项能力前，核对 Desktop、VS Code 或 JetBrains 的专项页面和当前应用版本。

03 · Cloud + mobile

离开电脑后继续运行，通常意味着云端执行。

Claude Code on the web 在 Anthropic 管理的虚拟机中运行任务，断开后仍可继续。常见起点是连接 GitHub 仓库、描述任务、在云端修改并审查结果或 PR。

适合云端

仓库已在受支持远端、环境可重建、任务较独立且不需要频繁本地干预。

先检查环境

依赖、网络访问、环境变量、secrets 和设置脚本决定云端能否复现本地工作。

手机是入口

Claude iOS / Android 应用可以启动和监控云任务，也能通过 Remote Control 操作本地会话。

把仓库交给云端前，确认代码、未提交文件、凭据和组织政策允许这种执行方式。不要把“本地有”误当成“云端也应该有”。

04 · Continue anywhere

名字都包含“远程”，执行位置却不同。

方式任务由什么触发Claude 在哪里运行
Remote Control你从手机或浏览器继续控制会话你的本机 CLI 或 VS Code
Dispatch从手机发送一项任务你的本机 Desktop
Cloud / Web在浏览器或手机启动云任务Anthropic 管理的云端 VM
Slack团队在频道中 @ClaudeAnthropic cloud
Channels聊天、Webhook 或监控事件你的本机 CLI

claude remote-control 用于启动可从其他设备访问的本地会话。跨界面交接还可能使用 --cloud、--teleport 或 Desktop 的 /desktop；订阅与版本要求见官方各专项页面。

05 · Integrations

把已有工具接入真实开发流程。

Chrome

测试 Web 应用、查看控制台、填写表单和调试页面。浏览器可能带登录状态，操作前要限制目标网站与动作。

GitHub / GitLab CI

自动 PR 审查、issue 分流、维护任务。明确触发条件、令牌权限、成本与输出去向。

Slack

从团队聊天中的 bug 报告或需求触发云端工作并返回 PR；注意频道可见内容与组织权限。

其他服务可通过 MCP 或 Desktop connectors 接入，例如 Linear、Notion、Google Drive 或内部 API。连接范围应遵循最小权限，并考虑工具返回的不可信内容。

06 · Decision guide

用任务场景做最后选择。

  1. 要在服务器或脚本中运行：优先 CLI。
  2. 要边写代码边看选区与 diff：优先当前 IDE 扩展。
  3. 要管理多个本地会话和可视化预览：考虑 Desktop。
  4. 要长时间运行、关闭电脑后继续：考虑 Web 云会话。
  5. 要离开工位但继续操控本机会话：考虑 Remote Control。
  6. 要测试真实浏览器行为：考虑 Chrome 集成，并限制可执行动作。
  7. 要从团队聊天触发仓库任务：评估 Slack + 云端权限与数据边界。

07 · 实战练习

为一个真实任务画平台决策卡。

  1. 选一项你本周要做的任务，写下代码位置、依赖、 secrets、是否需要 GUI 和预计时长。
  2. 分别评估 CLI、IDE、Desktop、Web：执行位置、上下文来源、验证方式和权限风险。
  3. 选择最简可行入口，写出不选其他入口的一个主要理由。
  4. 如果涉及云端或外部集成，列出缺失环境、数据边界和人工审批点。
  5. 在同一小任务中实际使用所选入口，并记录是否减少切换或审查成本。
完成标准你能明确任务在哪里执行、需要哪些上下文、离开电脑后是否继续，以及为什么当前平台比其他选择更合适。
