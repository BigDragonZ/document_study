# 06：进阶学习路线

## 学习目标

完成基础躲避游戏后，选择一个小范围功能继续深入，而不是同时学习所有手册章节。以下顺序从巩固 2D 基础逐步过渡到 3D。

## 1. 物理：先选对碰撞对象

官方物理入门区分四类 2D 碰撞对象：

- `Area2D`：检测重叠、进入和离开，也可影响区域内的物理属性。
- `StaticBody2D`：通常不移动的环境碰撞体，例如墙体和地面。
- `RigidBody2D`：由物理引擎模拟运动，通过力和冲量等方式影响。
- `CharacterBody2D`：由代码实现移动和碰撞响应，常用于需要精确控制的角色。

继续学习：

- `CollisionShape2D` 与 Shape2D 的关系。
- Collision Layer 表示“我在哪一层”，Collision Mask 表示“我扫描哪些层”。
- `_physics_process(delta)` 与固定物理更新频率。
- 不要通过缩放 CollisionShape2D 节点来调整形状大小，应使用形状自身的尺寸控制。

官方来源：[Physics introduction](https://docs.godotengine.org/en/stable/tutorials/physics/physics_introduction.html)

## 2. 动画：从帧动画到属性动画

躲避游戏已经使用 `AnimatedSprite2D` 播放序列帧。下一步学习 `AnimationPlayer`，理解轨道、关键帧、循环和动画切换。

建议练习：给开始界面添加简单的淡入或按钮强调动画，先不要同时引入复杂状态机。

官方来源：[Animation](https://docs.godotengine.org/en/stable/tutorials/animation/index.html)

## 3. UI：适应不同窗口尺寸

从 `Control`、Container、Anchor 和 Theme 入手。重点不是把界面摆得更复杂，而是让窗口尺寸变化时仍然清晰可用。

建议练习：给 HUD 增加最高分一行，并检查窗口缩放后文字和按钮是否仍位于预期区域。

官方来源：[User interface (UI)](https://docs.godotengine.org/en/stable/tutorials/ui/index.html)

## 4. 音频：区分音乐与音效

先学习音频流播放、总线和音量控制，再考虑空间音频。2D 小游戏可从背景音乐、受击音效和按钮音效开始。

建议练习：让音乐循环播放，受击时播放短音效，并提供静音开关。音频资源仍需遵守各自许可证。

官方来源：[Audio](https://docs.godotengine.org/en/stable/tutorials/audio/index.html)

## 5. 数据与存档：只保存必要状态

`res://` 指向项目资源；运行时的用户数据通常写入 `user://`。保存前先明确哪些状态需要跨启动保留。

- 最高分、简单设置：可以从 `ConfigFile` 或少量 JSON 数据开始。
- 复杂游戏状态：需要设计对象识别、序列化、加载顺序和旧状态清理。
- JSON 便于阅读和调试，但不能直接表达所有 Godot 类型，例如 Vector2 需要拆分或转换。
- 读取存档要处理文件不存在、解析失败和数据类型不符合预期的情况。

官方来源：[Saving games](https://docs.godotengine.org/en/stable/tutorials/io/saving_games.html)

## 6. 导出：验证编辑器之外的产品

导出不是简单复制项目目录。根据目标平台阅读对应指南，准备与编辑器版本匹配的导出模板和平台工具，然后检查导出包中的资源、输入、窗口尺寸和存档路径。

先在当前桌面平台完成一个可运行导出，再考虑 Web 或移动端；不同平台有各自限制和签名要求。

官方来源：[Export](https://docs.godotengine.org/en/stable/tutorials/export/index.html)

## 7. 3D：复用已知模式，学习新增维度

官方 **Squash the Creeps** 与 2D 躲避游戏有相似结构，但新增：

- 三维坐标与跳跃。
- 使用角色物理体移动并检测碰撞。
- 物理层和分组识别不同对象。
- 按时间间隔实例化怪物。
- 移动动画及运行时速度调整。
- 在 3D 游戏上绘制 UI。

建议先完成 2D 主线，再按“游戏区域 → 玩家 → 怪物 → 跳跃/踩踏 → 失败/重开 → 动画”的顺序推进。不要只把 2D 节点名批量替换成 3D 节点名，要重新理解坐标、重力和碰撞。

官方来源：[Your first 3D game](https://docs.godotengine.org/en/stable/getting_started/first_3d_game/index.html)

## 8. 后续查阅方法

1. 先用教程理解一个完整使用场景。
2. 在代码编辑器中对内置属性或函数使用 Ctrl + Click（macOS 为 Cmd + Click）打开对应文档。
3. 阅读类说明、继承关系、方法参数和信号，而不只复制示例。
4. 确认文档版本与项目版本一致。
5. 每次只增加一个小功能，并重新验证原有游戏闭环。

## 小结

进阶不是收集更多 API，而是在已有项目中解决一个明确问题：更可信的碰撞、更灵活的 UI、更好的反馈、可恢复的数据或可发布的构建。
