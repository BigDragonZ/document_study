# 05：完整 2D 游戏——Dodge the Creeps

## 学习目标

读完后，你应能解释官方 Dodge the Creeps 项目的场景职责、游戏状态和信号流，而不是只把代码视为一组彼此孤立的片段。

## 1. 先划分职责，再写代码

官方教程把游戏拆成四个主要部分：

| 场景/部分 | 主要职责 | 不应承担的职责 |
| --- | --- | --- |
| `Player` | 读取移动输入、播放动画、限制屏幕范围、检测受击并发出 `hit` | 决定全局计分、生成敌人、显示开始菜单 |
| `Mob` | 设置外观和初始运动、离屏后删除自己 | 修改分数、决定游戏开始或结束 |
| `Main` | 保存分数、控制 Timer、生成敌人、处理 `new_game()` 与 `game_over()` | 实现玩家每一帧的移动细节 |
| `HUD` | 显示分数和消息、提供开始按钮、发出 `start_game` | 直接生成敌人或运行游戏计时代码 |

这种划分的核心是：**对象处理自身行为，Main 协调整局游戏，HUD 负责界面并通过信号通知 Main。**

## 2. 玩家：输入、动画和碰撞

官方玩家根节点是 `Area2D`，包含 `AnimatedSprite2D` 与 `CollisionShape2D`。

- `Area2D` 能检测其他碰撞对象进入，并发出 `body_entered`。
- `AnimatedSprite2D` 根据方向选择 `walk` 或 `up`，再调整 `flip_h`/`flip_v`。
- `CollisionShape2D` 提供实际碰撞形状；仅添加节点而未设置 Shape 不会得到期望的碰撞范围。

移动逻辑有三个关键点：

1. 每帧从 `Vector2.ZERO` 开始收集四个方向输入。
2. 对非零方向调用 `normalized()`，避免斜向比直线更快。
3. 乘以 `speed * delta` 更新位置，再用 `clamp()` 限制在视口内。

受击时，玩家隐藏并发出 `hit`，同时延迟禁用碰撞形状：

```gdscript
hide()
hit.emit()
$CollisionShape2D.set_deferred("disabled", true)
```

`set_deferred()` 避免在引擎正在处理碰撞回调时立即修改物理属性。重新开始时，`start(pos)` 恢复位置、可见性和碰撞。

## 3. 敌人：可实例化的独立场景

官方 `Mob` 使用 `RigidBody2D`，并包含：

- `AnimatedSprite2D`：随机选择 `fly`、`swim` 或 `walk`。
- `CollisionShape2D`：定义碰撞范围。
- `VisibleOnScreenNotifier2D`：离屏时发出 `screen_exited`，让 Mob 调用 `queue_free()`。

教程把 Gravity Scale 设为 0，并调整 Collision Mask 防止敌人彼此碰撞。Main 只在生成时设置初始 `linear_velocity`，之后由物理引擎计算运动，而不是每帧直接改写 Mob 位置。

`queue_free()` 会在当前帧末尾安全删除节点。离屏清理既避免无用节点不断积累，也让每个敌人只关心自己的生命周期。

## 4. Main：状态、计时和生成

Main 根节点使用普通 `Node`，因为它主要组织逻辑，本身不需要 2D 变换。

主要子节点：

- `Player`：玩家场景实例。
- `StartPosition`（`Marker2D`）：出生位置。
- `MobTimer`：控制敌人生成频率。
- `ScoreTimer`：每秒增加分数。
- `StartTimer`：提供开局准备时间，设为 One Shot。
- `MobPath`（`Path2D`）与 `MobSpawnLocation`（`PathFollow2D`）：选择屏幕边缘的随机位置和方向。
- `HUD`：界面场景实例。

通过导出属性接收敌人场景：

```gdscript
@export var mob_scene: PackedScene
```

在 Inspector 中把 `mob.tscn` 赋给该属性后，Main 才能调用 `mob_scene.instantiate()`。实例创建后还要 `add_child(mob)`，否则它不会进入场景树。

生成流程可概括为：

```text
MobTimer.timeout
→ instantiate()
→ 设置 PathFollow2D 的 progress_ratio
→ 读取随机生成位置和方向
→ 添加少量随机角度与随机速度
→ add_child()
```

路径应按官方示意绘制，尤其注意顺时针方向；否则敌人朝向可能与预期相反。

## 5. 游戏状态与信号流

### 开始游戏

```text
StartButton.pressed
→ HUD 隐藏按钮并发出 start_game
→ Main.new_game()
→ 分数归零、清理旧敌人、重置玩家、更新 HUD
→ StartTimer.start()
→ StartTimer.timeout
→ MobTimer 与 ScoreTimer 开始
```

### 游玩与计分

```text
ScoreTimer.timeout
→ score += 1
→ HUD.update_score(score)
```

### 游戏结束

```text
敌人进入 Player
→ Player 隐藏、延迟禁用碰撞并发出 hit
→ Main.game_over()
→ ScoreTimer 与 MobTimer 停止
→ HUD.show_game_over()
→ 显示结束消息，之后重新显示开始按钮
```

这条链路说明信号与直接函数调用可以共存：Player 和 HUD 用信号把事件交给 Main；Main 作为协调者，再调用 HUD 的显示方法。

## 6. 用 Group 清理旧敌人

重开时，上一局敌人可能仍在屏幕中。官方做法是把 Mob 根节点加入 `mobs` 组，然后在 `new_game()` 中调用：

```gdscript
get_tree().call_group("mobs", "queue_free")
```

组适合对一类对象执行统一操作，不需要 Main 保存每个敌人的引用。

## 7. HUD 为什么使用 CanvasLayer

HUD 根节点是 `CanvasLayer`，让界面绘制在游戏内容上方。`ScoreLabel`、`Message`、`StartButton` 都是 `Control` 类型，使用 Anchors 和 Anchor Presets 布局，而不是只依赖固定像素位置。

`MessageTimer` 控制临时消息；`await $MessageTimer.timeout` 和 `get_tree().create_timer()` 可以表达简短的异步显示流程。

## 常见误区

- **实例化了 Mob，但画面中不存在。** 检查是否 `add_child()`，以及 `mob_scene` 是否已在 Inspector 赋值。
- **斜向移动更快。** 对输入方向先 `normalized()`，再乘速度。
- **碰撞回调中报物理状态错误。** 对碰撞形状的禁用使用 `set_deferred()`。
- **重开后旧敌人仍在。** 检查 `mobs` 组和 `call_group()` 清理逻辑。
- **游戏自动开始，按钮失去意义。** 接入 HUD 后，移除 `_ready()` 中用于测试的 `new_game()`。
- **节点或动画名称找不到。** 名称区分大小写，`$AnimatedSprite2D` 和动画名必须与场景/资源完全一致。

## 小结

完整项目不是把更多代码放进一个脚本，而是让玩家、敌人、Main 和 HUD 各自承担明确职责，再用实例化、信号、Timer 和组串起完整状态循环。
