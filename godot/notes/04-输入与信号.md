# 04：输入与信号

## 学习目标

读完后，你应能区分持续输入与离散事件，并通过内置或自定义信号让节点协作。

## 1. 两种输入处理方式

### 输入回调

`_unhandled_input(event)` 适合响应“发生了一次”的事件，例如按一下跳跃键、点击鼠标或打开菜单。

```gdscript
func _unhandled_input(event: InputEvent) -> void:
	if event.is_action_pressed("jump"):
		print("Jump pressed")
```

它关注的是事件本身，而不是每帧持续查询状态。

### Input 单例轮询

`Input` 是全局可访问的单例。`Input.is_action_pressed()` 适合在 `_process()` 中持续检查方向键、移动键是否处于按下状态。

```gdscript
func _process(delta: float) -> void:
	var direction := 0.0
	if Input.is_action_pressed("ui_left"):
		direction = -1.0
	if Input.is_action_pressed("ui_right"):
		direction = 1.0
	rotation += angular_speed * direction * delta
```

选择规则：

- “按住时持续移动” → 每帧轮询 Input。
- “按一下触发动作” → 输入回调或相应的单次动作 API。

## 2. Input Map 与输入动作

不要只把逻辑绑定到某个物理键。Godot 用**动作（action）**把“玩家意图”和一个或多个按键、手柄输入关联起来。

在 **Project → Project Settings → Input Map** 中可以查看和编辑动作。`ui_left`、`ui_right`、`ui_up` 等是项目预置动作；项目通常还应定义自己的 `move_left`、`jump` 等动作。

这样，玩家换键或增加手柄支持时，游戏逻辑仍然只读取动作名。

## 3. 信号是什么

信号（Signal）是节点在特定事件发生时发出的消息。其他节点可以连接信号，并在事件发生时调用接收函数。

例如：

- `Button.pressed`：按钮被按下。
- `Timer.timeout`：计时结束。
- 自定义 `health_changed`：生命值发生变化。

信号让发送方不必知道接收方的具体实现，从而减少耦合。玩家只负责发出 `health_changed`，HUD 决定如何显示，无需玩家直接操作每个界面元素。

## 4. 在编辑器中连接信号

以按钮控制运动为例：

1. 选中 `Button`。
2. 打开 Signals 面板。
3. 双击 `pressed`。
4. 选择挂有接收脚本的节点。
5. 连接并编写回调。

GDScript 回调通常命名为 `_on_节点名_信号名`：

```gdscript
func _on_button_pressed() -> void:
	set_process(not is_processing())
```

这里并没有修改按钮，而是切换当前节点的每帧处理状态。

## 5. 在代码中连接信号

动态实例化的节点通常需要在代码中连接。以下代码在 `_ready()` 中获取 Timer 并连接 `timeout`：

```gdscript
func _ready() -> void:
	var timer = get_node("Timer")
	timer.timeout.connect(_on_timer_timeout)

func _on_timer_timeout() -> void:
	visible = not visible
```

要点：

- 对信号对象调用 `connect()`，传入接收函数。
- `_ready()` 是连接已有子节点信号的常见位置。
- 如果重命名 Timer，节点路径也必须同步更新。

## 6. 自定义信号与参数

```gdscript
extends Node2D

signal health_changed(old_value: int, new_value: int)
signal health_depleted

var health := 10

func take_damage(amount: int) -> void:
	var old_health := health
	health = maxi(health - amount, 0)
	health_changed.emit(old_health, health)
	if health == 0:
		health_depleted.emit()
```

- `signal` 声明信号及参数。
- 对信号调用 `emit()` 发出消息。
- 接收方按声明的参数读取变化。
- 信号通常表示刚发生的事件，名称常用过去式或完成态，如 `died`、`health_changed`。

调用方必须保证发出的参数数量、顺序和含义与接收方预期一致。

## 常见误区

- **持续移动只响应一次。** 检查是否把按住状态误当成单次事件处理。
- **节点改名后信号失效。** 检查 `get_node()` 或节点路径是否仍指向原节点。
- **信号似乎触发两次。** 检查编辑器和代码是否重复连接，或初始化代码是否执行了多次。
- **玩家脚本塞满 HUD 操作。** 考虑由玩家发出状态变化信号，让 HUD 自己更新。
- **把信号当普通函数调用。** 使用 `signal_name.emit()` 发出，用 `signal_name.connect(callback)` 连接。

## 小结

Input 回答“玩家现在按着什么”，输入事件回答“玩家刚刚做了什么”，信号回答“游戏对象刚刚发生了什么”。三者配合，可以形成清晰、低耦合的交互流程。
