# 01：节点与场景

## 学习目标

读完后，你应能解释 Node、Scene、场景树和主场景分别是什么，并分清“运行当前场景”与“运行项目”。

## 1. 两个核心概念

Godot 游戏可以概括为：**一棵由场景组成的树，而每个场景又是一棵由节点组成的树。**

### 节点（Node）

节点是游戏的基本构建块。不同节点负责不同能力，例如：

- `Sprite2D` 显示二维图片。
- `Camera2D` 提供二维摄像机。
- `CollisionShape2D` 描述碰撞形状。
- `Timer` 处理计时。
- `Label` 显示文字。

节点具有以下共同特征：

- 有名称和可在 Inspector 中编辑的属性。
- 能接收引擎回调，例如每帧更新。
- 能通过脚本扩展属性和函数。
- 能成为另一个节点的子节点。

节点本身通常只提供一类能力。把多个节点组合起来，才形成完整的游戏对象。

### 场景（Scene）

把一组节点组织成树并保存，就得到场景。场景有一个根节点，可以保存为 `.tscn` 文件，也可以作为整体放入其他场景。

例如，一个玩家场景可以这样想：

```text
Player（CharacterBody2D，根节点）
├── Sprite2D（显示形象）
├── CollisionShape2D（描述碰撞范围）
└── Camera2D（让镜头跟随）
```

保存后，`Player` 不只是若干松散节点，而是一个可复用的整体。

## 2. 场景树与主场景

Godot 编辑器本质上是一个场景编辑器。一个项目可以有很多场景，例如：

```text
Main
├── Player（Player 场景的实例）
├── Level
│   ├── Ground
│   └── Obstacles
└── HUD
```

运行项目时，引擎需要一个入口，这个入口就是**主场景（Main Scene）**。主场景路径保存在 `project.godot` 中，通常通过编辑器设置，而不是手动修改文件。

- **运行当前场景**：只运行编辑器里正在编辑的场景，适合局部测试。
- **运行项目**：从主场景启动，适合验证完整流程。

| 操作 | 通用快捷键 | macOS 官方教程标示 |
| --- | --- | --- |
| 运行项目 | F5 | Cmd + B |
| 运行当前场景 | F6 | Cmd + R |
| 停止运行 | F8 | Cmd + . |

## 3. 编辑器中的三个常用面板

- **Scene 面板**：查看当前场景的节点树，添加、删除和组织节点。
- **Inspector 面板**：查看并修改所选节点的属性。例如选中 `Label` 后修改 `Text`。
- **FileSystem 面板**：管理项目内的场景、脚本、图片等资源。

新建空场景时，编辑器提供 2D Scene、3D Scene、User Interface 和 Other Node 等入口。它们只是快捷方式，并不限制你之后添加其他类型的子节点。

## 4. `res://` 是什么

`res://` 表示项目根目录。例如：

```text
res://scenes/player.tscn
res://icon.svg
```

Godot 编辑器的保存对话框通常要求把项目资源保存在项目目录内。养成按 `scenes/`、`scripts/`、`assets/` 分类的习惯，但不要为了目录结构牺牲简单性。

## 5. 最小操作流程

1. 新建项目并创建场景。
2. 添加一个 `Label` 作为根节点。
3. 在 Inspector 中把 `Text` 改为 `Hello World`。
4. 保存为 `label.tscn`。
5. 运行当前场景，确认窗口显示文字。
6. 将它设为主场景，再运行项目。

这个流程同时验证了节点、属性、场景保存和主场景设置。

## 常见误区

- **“一个项目只能有一个场景。”** 错。项目可以有任意多个场景，只需要指定一个主场景作为入口。
- **“运行按钮看到的都应该是整个项目。”** 不一定。运行当前场景只测试当前场景。
- **“节点越多越好。”** 不是。节点应承担明确职责，结构以清晰为准。
- **“Inspector 显示的名称就是代码名称。”** Inspector 常用 Title Case，GDScript 属性通常使用 snake_case；可悬停属性查看说明与标识符。

## 小结

节点提供能力，场景组织节点，主场景提供项目入口。先学会阅读和搭建场景树，再进入实例化与脚本会容易得多。
