练习 03：完整躲避游戏

前置知识与准备

  • 已完成练习 02。
  • 已读：完整 2D 游戏笔记。
  • 从官方 Your first 2D game 页面下载 dodge_the_creeps_2d_assets.zip。
  • 新建项目并按官方说明导入素材。不要用同名旧教程的 Godot 3.x 代码替代。

目标

完成 Dodge the Creeps 的最小完整闭环：

标题界面 → 开始 → 移动/生成敌人/计分 → 受击结束 → 重开

每个部分先独立验收，再连接下一部分。

第一部分：Player 场景

  1. 创建 player.tscn，根节点为 Area2D，命名 Player。
  2. 添加 AnimatedSprite2D 和 CollisionShape2D。
  3. 使用官方素材配置 walk、up 动画，并设置合适的碰撞形状。
  4. 添加脚本，声明 @export var speed、screen_size 和自定义 signal hit。
  5. 在 Input Map 添加 move_right、move_left、move_up、move_down，绑定四个方向键。
  6. 每帧收集方向，非零时归一化并乘速度；播放或停止动画。
  7. 用 position += velocity * delta 移动，再将位置限制在视口内。
  8. 根据水平/垂直方向切换动画及翻转属性。
  9. 连接 body_entered：隐藏玩家、发出 hit，用 set_deferred() 禁用碰撞。
  10. 编写 start(pos)，恢复位置、可见性和碰撞。

阶段验收

  • 单独运行 Player 场景时，四方向移动速度一致，斜向不会更快。
  • 玩家不能移出视口，动画方向正确。
  • _ready() 中的初始隐藏不会妨碍用测试代码调用 start()。
  • 受击回调只负责玩家自身状态和发出 hit，没有操作 HUD 或分数。

官方对照：Coding the player

第二部分：Mob 场景

  1. 创建 mob.tscn，根节点为 RigidBody2D，命名 Mob。
  2. 添加 AnimatedSprite2D、CollisionShape2D、VisibleOnScreenNotifier2D。
  3. 将 Gravity Scale 设为 0，按官方说明设置 Collision Mask，避免敌人彼此碰撞。
  4. 配置 fly、swim、walk 三种动画和碰撞形状。
  5. 在 _ready() 中随机动画并播放。
  6. 连接 screen_exited，让 Mob 调用 queue_free()。
  7. 把 Mob 根节点加入 mobs 组，供重开时统一清理。

阶段验收

  • 多次实例化 Mob 时，外观可随机变化，实例互不影响。
  • Mob 不受重力下落，离屏后会删除自己。
  • 所有 Mob 实例都属于 mobs 组。

官方对照：Creating the enemy

第三部分：Main 场景与生成流程

  1. 创建 main.tscn，根节点使用 Node，命名 Main。
  2. 实例化 Player，添加 StartPosition（Marker2D）。
  3. 添加三个 Timer：
节点 Wait Time 作用
MobTimer 0.5 秒 生成敌人
ScoreTimer 1 秒 分数加一
StartTimer 2 秒，One Shot 开局准备
  1. 添加 MobPath（Path2D）和子节点 MobSpawnLocation（PathFollow2D），按官方示意顺时针绘制闭合边缘路径。
  2. Main 脚本声明 @export var mob_scene: PackedScene 和 score，在 Inspector 赋值 mob.tscn。
  3. 把 Player 的 hit 连接到 game_over()：停止 ScoreTimer 和 MobTimer。
  4. 编写 new_game()：分数归零、清理 mobs 组、重置玩家、启动 StartTimer。
  5. 连接 StartTimer：超时后启动 MobTimer 和 ScoreTimer。
  6. 连接 ScoreTimer：每次超时 score += 1。
  7. 连接 MobTimer：实例化 Mob，随机 PathFollow2D 进度，设置位置、方向和速度，最后 add_child(mob)。
  8. 暂时在 _ready() 调用 new_game()，并把 Main 设为主场景进行测试。

阶段验收

  • 敌人从屏幕边缘随机位置生成，主要朝游戏区域内部运动。
  • 分数每秒增加，受击后敌人生成和计分都停止。
  • 再次调用 new_game() 后，旧敌人被清理，玩家恢复，分数从零开始。
  • mob_scene 未赋值、忘记 add_child() 等错误均已排除。

官方对照：The main game scene

第四部分：HUD 与完整闭环

  1. 创建 hud.tscn，根节点为 CanvasLayer，命名 HUD。
  2. 添加 ScoreLabel、Message、StartButton 和 MessageTimer。
  3. 使用官方字体、Anchors 和 Anchor Presets 完成布局；MessageTimer 设为 2 秒 One Shot。
  4. HUD 脚本声明 signal start_game。
  5. 实现 update_score()、show_message() 和 show_game_over()。
  6. 连接 StartButton：隐藏按钮并发出 start_game。
  7. 连接 MessageTimer：超时隐藏临时消息。
  8. 把 HUD 实例加入 Main，将 start_game 连接到 new_game()。
  9. 在 new_game() 更新分数并显示准备消息；在 game_over() 调用 HUD 的结束显示。
  10. 每次 ScoreTimer 超时同步更新 HUD。
  11. 删除 _ready() 中用于测试的 new_game()，让标题界面等待玩家点击 Start。

阶段验收

  • 启动项目先看到标题和 Start，不会自动计分。
  • 点击 Start 后出现准备消息，随后生成敌人并开始计分。
  • 受击后显示 Game Over，之后可以再次开始。
  • 连续重开三次，每次都满足：分数归零、旧敌人清理、玩家可操作、Timer 不错误叠加。
  • 调整窗口大小时，HUD 仍位于预期锚点区域。

官方对照：Heads up display

常见错误

  • 斜向速度异常。 输入向量先归一化，再乘 speed。
  • 碰撞后出现重复 hit 或物理错误。 延迟禁用碰撞，并在重开时恢复。
  • 敌人不生成。 检查 MobTimer 是否由 StartTimer 启动、Mob Scene 是否赋值、实例是否加入场景树。
  • 敌人全部朝外。 按官方方向重新检查 Path2D 的绘制顺序和方向计算。
  • 游戏结束仍加分。 game_over() 必须停止 ScoreTimer 和 MobTimer。
  • 绕过标题直接开始。 删除 _ready() 中残留的测试调用。
  • 节点路径报错。 $Name 区分大小写，且必须与当前脚本节点的相对路径一致。

拓展挑战（选做）

不增加新系统，只做平衡调整：让 MobTimer 的间隔或敌人速度随分数逐步变化，并设置合理下限/上限。

验收：开局仍有反应时间，后期难度可感知提高，参数不会变成零或负数。

完成标准

关闭本练习，仅根据场景职责图重新说明开始、计分、受击和重开的信号流；然后实际运行一次完整闭环，Debugger 无脚本错误。
