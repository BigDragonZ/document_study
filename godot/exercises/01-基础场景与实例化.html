练习 01：基础场景与实例化

前置知识与准备

  • 已读：节点与场景、场景实例化。
  • 新建一个 Godot 4.7 项目，使用默认 icon.svg。
  • 不需要编程或外部素材。

目标

完成两个场景：

  • label.tscn：显示文字的主场景。
  • main.tscn：包含一个可复用图标场景的至少 3 个实例，并证明默认值与覆盖值的区别。

第一部分：创建并运行主场景

  1. 新建场景，添加 Label 根节点。
  2. 在 Inspector 中将 Text 改为 Hello Godot。
  3. 把 Label 移到窗口中容易看见的位置。
  4. 保存为 label.tscn。
  5. 按 F6（macOS：Cmd + R）运行当前场景。
  6. 关闭运行窗口，将 label.tscn 设为主场景。
  7. 按 F5（macOS：Cmd + B）运行项目。

阶段验收

  • 两种方式都能显示 Hello Godot。
  • 你能说出 F6 测试的是当前场景，而 F5 从主场景启动。
  • project.godot 已记录主场景，不需要手动编辑该文件。

第二部分：创建可复用图标场景

  1. 新建场景，添加 Sprite2D 根节点并命名为 Token。
  2. 把 FileSystem 中的 icon.svg 拖到 Inspector 的 Texture 属性。
  3. 将图标放在场景原点附近的可见位置。
  4. 保存为 token.tscn。

这个场景现在就是可复用的 PackedScene。

第三部分：实例化并比较属性

  1. 新建 main.tscn，根节点使用 Node2D，命名为 Main。
  2. 选中 Main，用 Scene 面板的实例化按钮添加 token.tscn。
  3. 再添加两个实例，共至少 3 个。
  4. 将三个实例拖到不同位置，分别命名为 TokenA、TokenB、TokenC。
  5. 只把 TokenA 的 Scale 改为 (0.25, 0.25)。
  6. 打开 token.tscn，把源场景根节点的 Scale 改为 (0.5, 0.5) 并保存。
  7. 回到 Main，观察三个实例。
  8. 再把源场景的 Scale 改为 (0.75, 0.75)，观察 TokenA 与其他实例的区别。
  9. 点击 TokenA 的 Scale 属性旁的恢复按钮，观察它重新跟随源场景。
  10. 将 main.tscn 设为新的主场景并运行。

阶段验收

  • 三个图标位置可以分别调整，不会互相吸附或同步改名。
  • 未覆盖 Scale 的实例会跟随源场景默认值变化。
  • TokenA 在覆盖 Scale 后保留自己的值，不被源场景后续修改冲掉。
  • 恢复覆盖值后，TokenA 重新采用源场景默认值。

常见错误

  • 运行后还是 Label。 主场景仍是 label.tscn；把 main.tscn 设为新的主场景。
  • 拖进图片后看不到图标。 检查 Texture 是否赋值，以及实例是否位于窗口可视范围内。
  • 源场景修改没有影响某个实例。 检查该实例是否覆盖了同一属性。
  • 以为所有资源都会独立复制。 节点实例独立，但 Resource 可能共享；需要单独修改时使用 Make Unique。

拓展挑战（选做）

按照官方 Creating instances 的 Ball 示例创建一个带 PhysicsMaterial 的 RigidBody2D 场景。先观察共享材质的影响，再对一个实例的材质执行 Make Unique，验证只有该实例的弹性发生变化。

验收：你能用“源场景默认值、实例覆盖、共享 Resource”三个术语解释观察结果。

完成标准

不看步骤，从空项目重新完成一次 Label 主场景和 3 个 Token 实例，并向别人解释最后一次 Scale 实验的结果。
