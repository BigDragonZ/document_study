练习 04：扩展挑战

前置知识与使用方式

  • 已完成练习 03，开始、计分、失败和重开均正常。
  • 已读：进阶学习路线。
  • 以下全部为选做。 每次只选一项，完成后先验证原有游戏闭环，再开始下一项；不必按顺序，也不要求全部完成。
  • 修改前保留一份可运行的项目副本。

挑战 A：渐进难度

目标

让难度随分数提升，同时保留开局反应时间并避免参数失控。

步骤

  1. 把初始生成间隔、最小生成间隔、初始速度和最大速度设为语义明确的变量或导出属性。
  2. 在分数变化时计算新难度，不要在 _process() 中无意义地重复设置。
  3. 用 maxf() 限制 MobTimer 的最小 wait_time，用 minf()/maxf() 限制速度范围。
  4. 分别测试分数 0、30、60 时的生成频率和移动速度。
  5. 重开游戏，确认所有难度参数恢复初始值。

验收

  • 后期难度可感知提高，Timer 间隔始终大于零，速度不超过设定上限。
  • 重开后难度完全重置，不继承上一局加成。

常见错误

只修改了显示分数却忘记更新难度，或难度变量在 new_game() 中没有重置。

挑战 B：暂停与恢复

目标

用一个暂停菜单停止游戏世界，同时让菜单本身仍能响应输入。

步骤

  1. 创建一个暂停界面，包含继续按钮。
  2. 阅读 SceneTree 暂停与节点 Process Mode 的官方说明。
  3. 切换 get_tree().paused，并让暂停界面使用能在暂停时处理输入的 Process Mode。
  4. 在暂停前后观察玩家、Mob、MobTimer 和 ScoreTimer。
  5. 连续暂停/恢复三次，再测试游戏结束与重开。

验收

  • 暂停时玩家和敌人停止运动，分数不增加，敌人不继续生成。
  • 暂停菜单仍可点击，恢复后从原状态继续，而不是重新开始。
  • 重开不会把游戏永久留在暂停状态。

常见错误

把暂停菜单也设为暂停时停止处理，导致无法点击继续；或只隐藏画面而没有暂停 SceneTree。

官方来源：Pausing games

挑战 C：音乐与音效

目标

为游戏增加背景音乐、受击音效和静音控制。

步骤

  1. 使用官方教程素材或许可证允许的音频，记录素材来源。
  2. 添加背景音乐播放器并设置循环。
  3. 在游戏结束流程中播放受击音效，避免每帧重复触发。
  4. 增加静音按钮，通过音频总线或播放器状态控制声音。
  5. 测试开始、受击、重开和连续点击静音。

验收

  • 音乐不会因重开叠加多个实例，受击音效每次只触发一次。
  • 静音后所有目标声音都停止，取消静音后不会重复播放背景音乐。
  • Debugger 没有资源路径错误。

常见错误

把播放调用写进 _process()，或每次重开都新建一个音乐播放器而不清理旧实例。

官方来源：Audio

挑战 D：保存最高分

目标

关闭并重新打开项目后，仍能显示历史最高分；当前局分数仍应正常归零。

步骤

  1. 区分 score（当前局）与 high_score（持久数据）。
  2. 启动时读取 user:// 中的最高分；文件不存在时使用 0。
  3. 游戏结束时，只有当前分数更高才更新并保存最高分。
  4. 在 HUD 分开显示当前分数和最高分。
  5. 可以用 ConfigFile 保存简单键值：
var config := ConfigFile.new()
config.set_value("scores", "high_score", high_score)
var error := config.save("user://high_score.cfg")
  1. 读取时检查 ConfigFile.load() 的返回值，不要假设文件一定存在或有效。
  2. 测试首次启动、创造纪录、未破纪录和重新启动四种情况。

验收

  • 首次启动没有存档也能正常游戏，最高分默认为 0。
  • 只有破纪录时最高分上升，普通重开不会把当前分数与最高分混淆。
  • 完全关闭并重新打开项目后，最高分仍正确显示。
  • 存档写入 user://，不是只读或应视为项目资源的 res://。

常见错误

在 new_game() 中把最高分也归零，或忽略文件不存在/读取失败的情况。

官方来源：Saving games

挑战 E：导出可运行版本

目标

在编辑器之外启动游戏，验证它不只是“编辑器里能运行”。

步骤

  1. 阅读 Export 文档中当前桌面平台的指南。
  2. 安装与 Godot 版本匹配的导出模板，创建桌面导出预设。
  3. 确认所需图片、字体和音频都通过 Godot 资源路径引用。
  4. 导出到一个新的输出目录，不覆盖项目源文件。
  5. 启动导出的程序，完成一次开始、受击和重开。
  6. 如果完成过挑战 D，还要验证导出程序的存档读写。

验收

  • 不打开 Godot 编辑器也能运行导出的游戏。
  • 导出版本没有缺图、缺字体或音频路径错误，完整游戏闭环正常。
  • 导出文件与项目源文件分开存放。

常见错误

导出模板版本不匹配，或用编辑器之外的任意文件路径引用资源导致导出后丢失。

官方来源：Export

挑战 F：进入 3D（独立选做项目）

目标

在新项目中完成官方 Squash the Creeps，复用场景、实例化、信号和 UI 知识，同时理解 3D 新增概念。

步骤

  1. 从官方教程下载 3D 素材，不与 2D 项目混用。
  2. 依次完成游戏区域、玩家、怪物、生成、跳跃与踩踏、失败、分数和重开。
  3. 重点记录三维坐标、重力、CharacterBody3D、碰撞层和组与 2D 项目的差异。
  4. 最后添加角色动画和 UI。

验收

  • 玩家能移动和跳跃，怪物能生成，踩踏与受击结果可区分。
  • 分数、失败和重开形成闭环，UI 在 3D 画面上正常显示。
  • 能解释哪些结构复用了 2D 经验，哪些行为必须由 3D 物理和坐标实现。

官方来源：Your first 3D game

完成标准

至少完成一项扩展，并给出三条证据：新功能的运行结果、原有游戏闭环仍正常、重开或重新启动后的状态符合预期。其余挑战可以保留为后续计划。
